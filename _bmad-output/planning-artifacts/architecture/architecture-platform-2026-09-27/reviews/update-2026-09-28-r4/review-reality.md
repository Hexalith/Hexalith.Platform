## Implementation evidence boundaries to preserve

1. **Candidate proof:** before accepting CI evidence, implement the shared revision policy, package transport, hash-to-loaded-artifact mapping and cache-substitution rejection. A commit label, manifest hash or package version does not satisfy AD-5. Lines 451, 464 and 465 already own this work.
2. **Attachment proof:** the current metadata-only state cannot establish holders, hold expiry, withdrawn outcomes or retention caused by an attached failure. Qualification must exercise owner completion, cancellation and interruption on the actual hosted runner, preserving failure evidence without assuming a killed process can finish its cleanup handler. The same-job resource boundary makes eventual host disposal possible; it does not create durable results automatically.
3. **Fencing proof:** official defaults are not a measured drain for this installation. Establish the credential issuer, reissuance denial and relevant authentication/request lifetimes, and prove that old authority cannot commit after operational takeover. Neither Helm nor GitHub cancellation supplies the epoch protocol by itself.
4. **Recovery proof:** the current report establishes documentary ordering. It does not prove namespace-specific Scheduler cleanup, broker reconstruction, admission-projection rebuild, recovery-hook epochs or the forward catalog generation. These remain first-staging and production/drill acceptance work. EventStore's existing prepare/ready/commit statement alone does not establish the added semantics.
5. **Dated infrastructure observations:** earlier cluster, registry, GitHub permission and ingress findings remain dated observations, not newly verified state. Recheck them at their existing gates. Preserve the single-node/shared-service, preview-package, notification, key-custody and RPO risks; this update supplies no evidence to retire them.

The unchanged prior evidence includes the Aspire Gateway/secret export limitations, Traefik and cert-manager Gateway API fit, Dapr vault-token startup loading, registry anonymous access and garbage collection, GitHub permission/plan constraints and observed cluster remediation inventory. Those were not re-probed here because this update changes their governing policy neither materially nor implicitly.
