# Coupled installation decision

## Why

The coupled EXT-SECRETS-1 / EXT-HOST-1 build needs concrete independent installation, enrollment, recovery and coordinated protection inputs. The inspected cluster supplies application scaffolding, but no qualified semantic custody installation or complete role enrollment. Owners need a reviewable resource and execution plan before the build can resume its dependent work.

## Capabilities

- **CAP-1**
  - **intent:** Owners can select a concrete custody construction.
  - **success:** The decision packet names proposed non-AWS MVP workloads, independent failure/administration domains and the exact backend resource identities still needed from owners, while keeping source and installed evidence distinct.
- **CAP-2**
  - **intent:** Independent operators can supply and verify installation authority.
  - **success:** D1–D9 identify each missing identity/resource/access/trust return and its accountable owner; distinct human administrator/deputy appointments and independently verified current enrollment are required, with no private values in the packet.
- **CAP-3**
  - **intent:** Maintainers can resume the coupled build and later install the reviewed result.
  - **success:** The command companion binds actual source prerequisites, exact original recovery mappings, conditional installation commands and verification to the owner-return bundle; this planning work executes no deployment or qualification.
- **CAP-4**
  - **intent:** Owners can agree replacement dates coordinated with protection.
  - **success:** Owners supply actual non-AWS provider readiness/completion/recovery bounds and coordinated protection/Platform dates; complete exact replacement acceptance precedes any cohort reservation. Prior AWS-derived date proposals are withdrawn.

## Constraints

- Preserve host 192.168.1.30, Parties Branch B, L/S/O/H/R=300/30/600/86400/604800, every original journal and OQ-5.4-1. Accepted Platform records/date remain historical authority until explicit replacement acceptance; availability does not change.
- AWS is excluded from MVP by explicit owner direction. Retain existing Kubernetes/Dapr/OpenBao for its observed operational-secret scope and keep all application infrastructure access through Dapr. No qualifying non-AWS semantic backend was established; ordinary OpenBao/Raft remains unqualified for physical non-revival.
- Active choices are reuse of an independently qualifying non-AWS installation or implementation/qualification of a non-AWS semantic infrastructure component. Actual backend/host/appliance/current-authority/archive resources remain owner inputs. The current AWS reference executable/profile/image preparer cannot become a non-AWS runtime through configuration; its account/region/native-key counts and wait interval are not MVP requirements.
- Administrators, independent public trust, installed hashes and physical/holder/survivor evidence require actual owner-provided or installation-derived facts. The observed local Dapr CA does not enroll qualification roles.
- Missing authorizer/control/closure/receiving/locator/role/currentness services and EventStore G1–G7 source/package/installation evidence stay open; reference strings cannot implement them.
- Read the adopted full draft and decision/runbook companions together. Preserve the legacy draft's frozen intent and draft status. All remaining D1–D9 questions stay unresolved until their accountable owners answer.

## Non-goals

- Provisioning, spending, deployment, trust enrollment writes, Live/Full execution, native physical experiments, consumer seam use, OQ attempt reservation or dependency availability changes.
- Selecting Product policy, minting approval evidence, replacing authority after loss or converting a source/component pass into physical qualification.

## Success signal

The draft contains verified installation findings and concrete D1–D9 choices, while the packet supplies exact conditional commands, ownership and verification. Governing records, historical evidence and frozen constraints remain unchanged. Actual deployment/qualification remains explicitly dependent on owner returns and later operational authorization.

## Open Questions

- **D1–D4:** Choose actual non-AWS backend/placement/scope; supply real resources/access, independent compute/role trust and primary/deputy appointments. No such appointment or independent role anchors were discovered.
- **D5–D8:** Supply missing owning implementations/stores, release/transport/closure measurements, complete EventStore physical/source/package/installed profile and all host identity/service bindings.
- **D9:** Platform and EventStore owners supply coordinated dates based on actual non-AWS provider bounds; prior estimates are withdrawn; the register owner later accepts only complete exact replacement packets. No date is accepted by this planning artifact.
