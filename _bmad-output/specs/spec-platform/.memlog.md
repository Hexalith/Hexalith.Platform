- (constraint) Ownership: Platform owns shared hosting, composition, promotion and recovery; modules own domain behavior, server lists, readiness semantics, public operations, critical flows, smoke suites and authoritative-state inventories. Platform implements no domain behavior and no second orchestration framework (spine paradigm, AD-1).
- (constraint) One Platform-owned Aspire model composes every environment; no AppHost runs in production; the retained application Helm package is the only staging/production deployment definition (AD-1, AD-2).
- (constraint) Only the active root's direct references/ declarations are initialized: no recursive or remote submodule updates, nested submodules stay uninitialized (deinitialize accidental ones), no ancestor/sibling/package fallback. Local = project references + Debug; CI/CD = NuGet + Release (AD-4, AD-5).
- (constraint) Platform environments run configured real services only; test doubles live solely in module-owned isolated tests.
- (constraint) Readiness is module-defined; process-running is not readiness; a required service without usable readiness evidence is a configuration error. Default test startup deadline 10 min, overridable only by a justified finite value shown in diagnostics.
- (constraint) Test environments are run-owned (AD-10): local success cleans, local test/startup failure retains, explicit local cancellation cleans only its own resources, CI always cleans including partial provisioning; cleanup never touches another run or a hosted environment; results and diagnostics survive cleanup.
- (constraint) Hosted: designated Kubernetes installation 192.168.1.30; staging hexalith.com, production tache.ai; supporting infrastructure may be shared only with per-environment application data, credentials and namespaces (AD-8).
- (constraint) Identity: existing shared Keycloak, separate staging and production realms; production admission is Administrator-granted group membership only, never by default, promotion or copied staging membership (AD-6, AD-14).
- (constraint) Promotion ships the same retained package and image digests that passed staging; evidence binds to the exact release; absent evidence is never a pass (AD-2).
- (constraint) Production verification defaults: 10 min to rollout readiness; 5-min verification window; failure on 60 continuous seconds unavailable, two consecutive smoke failures 30 s apart, or a missing result; one failed probe or restart alone does not fail. Defaults to validate in staging, not availability guarantees.
- (constraint) Recovery: exactly one automatic attempt to the recorded working baseline (10 min readiness, same 5-min verification); never cycle older releases; every non-working outcome sets a durable promotion stop cleared only by Administrator (spine Release and Recovery Acceptance).
- (constraint) NFR-1: application rollback never rewinds business data, event history, credential rotations or key generations; the automatic path requires previous-version-compatible schemas and event formats; incompatible releases use the Administrator-approved mode with a planned recovery (AD-3, AD-15).
- (constraint) NFR-2: RPO <= 1 h; RTO <= 4 h outage-to-verified-service including detection, response and capacity; runs every 30 min; frequent points 7 days, daily 30 days; encrypted off-primary copies with independent access and keys; alert when newest usable point > 1 h.
