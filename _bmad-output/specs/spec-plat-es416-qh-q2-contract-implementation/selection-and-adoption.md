## Registry and pipeline

The compiled registry root is a closed typed value with required `schema` constant `hexalith.qualification-selection-registry.v1`, `qualificationSuites:L<SuiteKey>[1,4096]`, and `entries:L<SelectionEntry>[0,4096]`. `SuiteKey` is exactly `{moduleId:I,suiteName:I}`, unique and sorted ordinally by that pair; entries sort by their exact key. Module/suite designation is checked **before** matching source bytes, so drift cannot lose its qualification designation. A designated key with zero matching complete entries refuses. Registry bytes use D2 encoding and are embedded in the tool content; no external registry file is accepted.

Each SelectionEntry is a closed typed value with all fields required: `moduleId:I`, `suiteName:I`, `manifestContentIdentity:H`, `entryContentIdentity:H`, `mode:E(source,package)`, `suiteContentIdentity:H`, `profileArtifactRef:Reference`, `configurationArtifactRef:Reference`, `testSetArtifactRef:Reference`, `inventoryArtifactRef:Reference`, `operationContractRef:Reference`, `consumerArtifactId:I`, `consumerContentIdentity:H`, `consumerAdoptionRef:Reference`, `descriptorSchema` constant `hexalith.test-environment.v2`, `resultSchema` constant `hexalith.test-result.v2`, `credentialSchema` constant `hexalith.test-endpoint-credentials.v2`. Types are from D1. Entry key is the exact module/suite/manifest/entry/mode tuple. Multiple entries for a key refuse, even if their values match. Registry entries are reviewed/hashed with owning tool changes, not self-authenticating adoption receipts.
