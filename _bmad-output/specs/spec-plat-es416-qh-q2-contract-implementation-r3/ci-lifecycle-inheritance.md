# CI lifecycle inheritance in the proposed v2 qualification contract

Revision `PLAT-ES416-QH-Q2-R3`. This companion applies the [November 11 published v1 lifecycle](../../../docs/contracts/test-environment-v1.md#ci-ownership-recovery-and-finalization) to the [proposed v2 handoff](../../../docs/contracts/test-environment-v2.md#descriptorresult-agreement). It governs the lifecycle wording in R2's implementation plan, serialization, credentials, observation/report rules and RF acceptance matrix. Qualification still adds typed bindings to the paired v2 descriptor and result. Use the existing terminal, attachment, retention and cleanup fields and diagnostics.

## Timeout, cancellation and first outcome

- A **CI helper deadline** uses the same cooperative interrupt as a runner cancellation. If it supplies the owner's first terminal outcome, the tool records `cancelled` and ends active holds as `withdrawn` with reason `ci-job-cancelled`. The helper independently records `timedOut` in `execution.json` and returns 124. This is distinct from a native TRX `Timeout` row, which retains the proposed D5 failed-row mapping, and from local startup/execution timeouts, which retain surviving resources for exact `down`.
- Deliver cooperative `SIGINT` only to the gated muxer and tool. The helper does not forward timeout or cancellation signals to composed processes. When the tool can cooperate, it records withdrawal before stopping them. The six-second cancellation escalation to `SIGTERM` (or escalation on a second runner signal), the 8.5-second cancellation kill, the 120-second timeout kill and the runner's own process-tree kill can interrupt that ordering. A CI AppHost can then stop when its stdin closes. Preserve the actual observation and let exact `down` withdraw remaining active holds before stopping what survives. A forced stop gives no evidence of prior withdrawal, successful reset or complete cleanup.
- Keep the first committed outcome, cause and time and the original hold/deadline and attempt identities. A timeout, later cancellation, archive failure or cleanup retry cannot relabel them. If cooperative recording was interrupted, use existing recovery and unavailable/partial-startup handling with the originally issued identities. Keep helper telemetry, the native report, the owner terminal and cleanup observations independently attributable. A missing report leaves completion unavailable and a missing lifecycle observation grants zero qualification credit.
- Pass the actual workflow job status to `down` via `HEXALITH_CI_JOB_STATUS` (`success`, `failure`, `cancelled` or empty). End active holds as `ci-job-cancelled` when job status is `cancelled`, the terminal is missing, or the terminal is `cancelled` or `withdrawn`. Other recorded terminals end holds as `ci-job-completed`, including a failed terminal in a failed job. A missing terminal can determine the hold reason without establishing that the owner was cancelled. Owner cancellation requires an actual cancellation, including the helper interrupt.
- A later attach to an owner with a `cancelled` terminal receives `HXR035 owner-cancelled`. Use `owner-withdrawn` only when the owner's own recorded terminal is `withdrawn`. An attached run can end `withdrawn` on expiry or environment withdrawal independently of the owner's terminal.

## Exact-owner recovery and cleanup

1. Keep the external, durable, link-free CI receipt as operational recovery metadata. Bind the owner run, attempt, environment and repository/workflow run/attempt/job before allocating a workspace or service. Keep the receipt outside deleted workspaces. It confers no qualification or candidate credit.
2. After normal completion or its own timeout, the helper runs exact `down --run-id <owner-run-id>`. The helper derives its timeout from remaining step/job budgets so both that path and the finalizer fit. After runner cancellation, the independent `always()` finalizer owns `down`. It also retries cleanup after failure or partial startup.
3. The finalizer stops surviving tool processes, then re-reads the receipt. If it is absent, stop the other recorded-session processes and re-read again. An orphaned tool may have written a late receipt. Only a still-absent receipt permits `not-allocated`. A receipt sends cleanup through verified exact `down`. Leave composed resources identified by the owner run tag to that path once the receipt is present.
4. Verify the durable owner and repository/run/attempt/job bindings before invoking `down`. A missing, unexecutable or unverifiable tool yields `tool-unavailable` with unverified cleanup and retained declared diagnostics. Cleanup can be `complete` only with verified discovery and zero owned resources. Unknown discovery, leftovers or failed owner verification remain visible and require exact-owner recovery. Preserve peer processes, resources and data. Retain only the existing classified and redacted results, attachments and declared diagnostics outside deleted workspaces. Exclude private tokens, credential files and raw logs.
5. End v2 module access on cancellation, withdrawal, revocation or the original expiry. The owner's bounded internal reset retains its original deadline and use limits and may undo only the admitted owned fault. Reset failure stays visible. Recovery and retry cannot reopen access, extend deadlines, admit a new fault, rewrite results or extend deletion to failure-retained local data.

## Focused acceptance additions

These cases extend the R2 RF matrix after exact-design acceptance. Use fake clocks, signals, helper/tool processes, receipts, ownership/discovery and diagnostics. Q5 still requires separately authorized hosted observation of actual cancellation, partial startup, reset and teardown.

| LC-01 · RF-05/07/11 | Helper deadline with an active hold, an originally failed terminal, a native TRX `Timeout` row and a local timeout variant | The cooperative CI timeout records owner cancellation when the first terminal is unset, withdraws the hold with `ci-job-cancelled`, records helper `timedOut`/124 and takes exact-down. An earlier outcome/cause/time survives. Native row mapping and local timeout retention stay distinct. |
| LC-02 · RF-05/07/10 | Actual job status combined with a missing, `cancelled`, `withdrawn`, `passed` or `failed` terminal. | LC-03 · RF-05/07/11 | Cooperative SIGINT, escalation, lost stdin, hard runner kill and interrupted startup | Signals target the muxer/tool. | LC-04 · RF-05/07 | Normal and timeout down, independent cancellation/failure retry, present receipt, persistently absent receipt, late receipt and mismatched durable bindings | The exact owner is recovered, including a receipt written by an orphaned tool during recorded-session teardown. `not-allocated` requires the last re-read to be absent.
