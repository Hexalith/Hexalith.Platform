### Architecture delta and spec reconciliation

**F1 — Deferred declared identity never joined the completed composition path.** Source resolution derives `activeIdentity = Path.GetFileName(activeRoot)` and creates the active source mapping under that name (`references/Hexalith.Builds/src/libraries/Hexalith.Builds.Tooling/Workspace/WorkspaceRootResolver.cs:125-132`). Platform looks up the canonical declaration owner such as `Hexalith.Parties` and refuses if absent (`src/Hexalith.Platform.Composition/PlatformServerBindings.cs:31-35,57-63`). The same actual Parties declaration/project binds one server with identity `Hexalith.Parties`; substituting the resolver-derived `Hexalith.Parties-wt2` identity throws `parties/domain: project: mapped source project is unavailable` (`evidence/epic-1-retro-2026-10-22/root-identity-repro-output.txt:1-2`). This is a binding-level reproduction using current Release assemblies, not a full cloned-workspace launch. Duplicate-package guards also consume the directory-derived identity (`SourceMappingValidationTask.cs:113-130,174-178`).

The explicit Story 1.3 decision deferred declared identity until Stories 1.5/1.12 (spec-1-3:133; deferred-work.md:350-352). Those stories are now done, yet the integration remains absent. Parties' documented clone uses the canonical name (`references/Hexalith.Parties/README.md:28-29`), which explains the scope of its successful historical proof without proving arbitrary root layouts.

- **Instance: fix now, proposed A1.** Reuse validated v2 identity for standalone active roots and cover renamed roots and source/package duplicate detection; retain the documented legacy contract where applicable.
- **Prevention:** give prerequisite-dependent deferrals an explicit closure check when their destination stories finish. No new naming restriction is written into the spec.
- **Provenance:** adversarial and edge-case lenses independently identified this same boundary; consolidated into one finding.

**F2 — Enrollment guide omits Platform executable registration.** The guide proceeds from static adoption to `run`/`debug` for the active module (`docs/domain-module-enrollment.md:177-195`). The ordinary runner's default project map contains Parties, EventStore, Tenants and Memories only (`PlatformServerBindings.cs:11-20`); `Resolve` refuses an unregistered owner server even if its declaration and mapped source are valid (:57-63). `ComposeRun` constructs default options without exposing the caller-supplied `Projects` override (`PlatformAppModel.cs:71-99`). The starter/kit test checks declaration validity and static disposable workspaces (`DomainEnrollmentKitTests.cs:12-19,74-107`), so those passes cannot establish that a new Folders/Projects owner reaches the documented runtime step. Existing hard-coded domain registrations are separately acknowledged in the Story 1.12 deferral (spec:88).

- **Instance: fix now, proposed A2.** Document the Platform-owned executable/configuration/routing binding handoff before run/debug, identify its owner and the required acceptance record. Verify the handoff on the next real owner adoption rather than claiming static validation registers runtime projects.
- **Prevention:** follow the published guide from a module absent from the default binding table before calling the kit complete. This proposes a documentation/contract reconciliation; it does not automatically expand the declaration schema or add domain code to Platform.
- **Provenance:** adversarial lens, rechecked against the actual default caller and binding failure branch.

Other adoption failures from intentionally uninitialized nested references, historical code/evidence and pending inventory are not treated as new regressions or permission to initialize nested submodules.

- **Instance: defer to the Parties owner's already-recorded enrollment work, tracked by A3.** Restore tool-mapped catalog authority in a way compatible with ordinary owner release CI, then gate the actual reference checkout's relevant adoption rows.
- **Prevention:** test the real pinned consumer as well as a synthetic kit fixture after owner build-file changes. Historical approval of the 1.12 integration does not mean the later enrollment validator passed.
