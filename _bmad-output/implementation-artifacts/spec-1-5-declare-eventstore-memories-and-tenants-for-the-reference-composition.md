## Intent

**Problem:** EventStore, Memories and Tenants have no module-owned v2 declarations, so Platform cannot validate their real services and readiness for the reference composition.

**Approach:** Add one declaration per repository from its current services, Dapr roles and health endpoints. Validate the set together.

## Boundaries & Constraints

**Always:** Use hexalith.module-manifest.v2 and complete all five schema groups. EventStore has no domain dependency; Memories and Tenants name only their actual EventStore dependency, with no invented domain dependency. Required servers have usable /ready checks. Every declared Dapr role has a logical capability, recovery class and configuration key. Declare the three approved Memories provider SDK exceptions and its direct Redis coordination separately as transitional. Set lifecycle.tasks to [] in all three declarations: current startup work is in-process, not independently executable or proven complete by readiness. Keep module owners responsible for their declarations and review.

**Never:** Add cross-module wiring to the Tenants AppHost; compose or launch the Platform model (1.6); complete Dapr component-name rebinding (1.7); claim that /ready proves Tenants bootstrap or EventStore admin dependency health; expose a legacy Memories MCP server as an enrolled MCP surface; invent a Tenants synthetic-tenant creation task (3.5 prerequisite); modify the v1 manifest contract.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Joint enrollment | Three v2 files | Validation succeeds with unique identities | No partial declaration set |
| Required service | Each enabled required server | Declares its actual app/resource IDs and usable /ready check | Missing readiness fails with source and field |
| Memories exceptions | Four direct provider uses | Graph, search/vector and SET NX are named approved exceptions; Redis coordination is marked transitional | Any fifth exception or unmarked coordination fails review |
| Minimum environment | EventStore and Memories | No invented domain dependency | Reject accidental domain dependencies |

## Design Notes

The v2 validator checks that task executable paths exist. Current startup work is largely hosted services, and the Tenants synthetic-tenant task is assigned to Epic 3. The 2026-10-11 decision is to declare empty task lists now, with no redundant /ready wrappers; later owning stories add runnable tasks. Story 1.7 binds logical component keys that current code still hardcodes.

Story 1.7 binding keys are `Dapr:StateStoreComponent`, `Dapr:PubSubComponent`, `Dapr:SecretStoreComponent`, `Dapr:ConfigurationStoreComponent`, `AccessTelemetryLifecycle:StateStoreComponent`, `AccessTelemetryLifecycle:SecretStoreComponent`, `AccessTelemetryLifecycle:ConfigurationComponent`, and `Embedding:CredentialNamespace`. They are declaration-stage inputs in Story 1.5; current services still use literal Dapr component names and tenant credential conventions. `Memories:LlmComponentPath` is the consumer-supplied YAML path input for the Memories Aspire extension.

The `Authentication:JwtBearer:SigningKey` inputs describe the existing non-Production symmetric mode; production gateway and Tenants domain hosts use OIDC authority with no signing key. Clock source tokens are supplied through each `Clock:Sources:*:AuthenticationToken` field from the logical clock-source secret namespace. `retentionSeconds` is the Dapr configuration item in `access-telemetry-config`; `AccessTelemetryLifecycle:RetentionSource` selects that Dapr authority.

The v2 schema permits colon-separated configuration keys but not underscores or indexed wildcards. `EventStore:AppChannelToken` and `Tenants:AppChannelToken` are declaration-stage secret inputs whose values must be materialized as `APP_API_TOKEN` on their respective hosts; neither service reads those logical names. The logical `Clock:SourceAuthenticationTokens` secret input maps values to each configured `Clock:Sources:<index>:AuthenticationToken` runtime field; HTTPS egress destinations come from each corresponding `Clock:Sources:<index>:Endpoint`. These mappings belong to the reference composition in Story 1.6 and do not change the v2 schema or runtime configuration contract.

The Tenants bootstrap is an in-process hosted service that sends a command only when a global administrator ID and delegated human credential exist. `Tenants:BootstrapGlobalAdminEnabled=false` is an explicit recovery disable; omission retains the current enabled behavior. In authority mode, `EventStore:Authentication:Authority` supplies the token endpoint base, `ClientId` and `Username` are configuration, and `Password` is a secret. `EventStore:Authentication:Authority/protocol/openid-connect/token` in the egress inventory denotes the derived HTTPS token endpoint. `EventStore:DataProtection:PersistToStateStore` opts the domain server into a shared cursor key ring; the development default remains unchanged. The production Memories Conversation component reads `llm-secret`/`OPENAI_API_KEY` through Dapr `secretstore`; the schema-valid logical `Conversation:ProviderApiKey` secret input maps to that YAML reference in Story 1.6. The development `conversation.echo` component has no provider credential.

Memories' logical `Memories:AppChannelToken` and `Memories:DaprApiToken` secrets must materialize as separate `APP_API_TOKEN` and `DAPR_API_TOKEN` environment variables on the core server, telemetry service and clock host. Production startup requires both values. `Authentication:JwtBearer` inputs configure the core server only: production uses OIDC authority; development may use a symmetric signing key. OIDC egress entries cover metadata and JWKS discovery from the configured EventStore, Memories and Tenants authorities, including Tenants API authority aliases. Memories Conversation provider egress follows the selected component YAML's provider endpoint; the manifest does not choose an OpenAI host.

The EventStore workload issuer uses its own client ID and secret in authority mode, distinct from inbound JWT validation. `Authentication:WorkloadIssuer:ClientSecret` is a direct runtime configuration key backed by the logical `workload-issuer-client-secret` secret; it needs no environment alias. Its optional explicit token endpoint or the endpoint discovered from the configured JWT authority drives outbound HTTPS egress. The v2 schema has no `http` egress protocol. Google/Ollama embedding provider entries use `tcp` to cover their configured HTTP or HTTPS URLs; the destination URL determines the application protocol and TLS use. The OIDC token endpoint remains HTTPS in production.

The EventStore gateway's `AdminOperationalIndexHostedService` is not an external-effect worker and has no disable control. It rebuilds gateway-owned routing indexes from domain `admin/operational-index-metadata`, and the request path reads them: `DaprDomainQueryHandlerRegistry` reads `admin:query-types:*`, `DaprCommandAggregateTypeResolver` reads `admin:type-catalog:commands:*`, and startup fills the named-projection route catalog. Disabling it would break routing after a fresh or restored state store. The Memories capability probe differs: it writes throwaway probe keys and can safely be disabled. `DaprRateLimitConfigSync` reads tenant rate-limit overrides from the `configstore` Dapr configuration component, declared as role `rate-limit-configuration`; its readiness check reports Degraded, not Unhealthy, when the component is absent. The opt-in `EventStore:DomainServices:ConfigStoreName` input names a Dapr configuration store for domain-routing overrides; it is null by default. Because v2 `callers` apply to a whole interface, Memories splits its telemetry surface by caller to match the owner ACL: `memories` → write/heartbeat/validate, `memories-access-telemetry-inspector` → inspect, and `access-telemetry-adapter` → physical-reclamation-evidence.

The two clock verifier settings (`AccessTelemetryLifecycle:AttestationVerificationKey` and `ClockSignerKeyEpoch`) reach the clock host in the local Aspire composition.
