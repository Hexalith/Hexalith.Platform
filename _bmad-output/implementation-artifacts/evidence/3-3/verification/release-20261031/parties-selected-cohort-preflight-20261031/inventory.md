## Credential and policy limitations retained

The existing Parties local Keycloak client mappers issue tenant/domain/permission claims but contain no eventstore:surface mapper. That is issuer configuration, not permission for a receiver/proxy to stamp ui or agent. The default selected Keycloak path therefore cannot establish successful catalog human calls without an explicitly owned issuer prerequisite; the feature profile must not pretend otherwise. Existing exact signed tests can supply a legitimate surface claim. Hosted identity realm generation is outside this story.

Memories workload proof, real gateway grants and authority were added by the existing PartyMemoryOwnedRuntimeTests qualification profile, not by the AppHost's default optional REST-search graph. No new business operation or transport is proposed. Direct REST search/ingestion stays outside the EventStore catalog under its existing JWT, tenant and APP_API_TOKEN controls.

## Required source qualification

## Actual Admin.Server HTTP sink correction

DaprClient constructs the invocation requests. Every actual service-invocation send in the eleven Dapr-backed admin services uses an injected IHttpClientFactory default/named client and SendAsync. Comments mentioning InvokeMethodAsync are historical. AddEventStoreRouteCatalog installs RouteCatalogStateHttpClientFilter on every factory client, wrapping the final primary sink in RouteCatalogInvocationHandler. See admin-factory-send-sink.json for exact source/hash/line evidence. This corrects the initial incomplete inference that DaprClient itself sent these requests. Real-socket source qualification and committed versioned technical target membership remain pending; no new transport is required.
