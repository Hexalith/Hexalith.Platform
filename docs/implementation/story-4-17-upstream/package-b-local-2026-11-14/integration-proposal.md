# Package B broker and Dapr experiment proposal — not executed

Prepared November 14, 2026 for EventStore 3.21 and Platform 4.17. This is a proposal for later, separately authorized execution. It is not an admitted run, a supported runtime or a qualification input. The local component patch and its protocol-peer tests cannot establish RabbitMQ routing behavior, Dapr API error mapping or persisted effects. Neither parent story closes.

The experiment asks one question: with opt-in mandatory publishing, does a publication to the physically unbound `qualification.missing-binding` topic fail conclusively through the component, and later through Dapr, within the existing deadlines? A bound positive control must keep exactly one effect. It also checks that concurrency, duplicate application IDs, cancellation and channel replacement never attribute a return to the wrong publication. Package A's NACK, revoked-credential and recovery experiment, and Kafka, stay separate.

## Component experiment sequence

A maintainer harness calls the public component `Publish` against the isolated broker, with the metadata above. It retains monotonic elapsed time, the exact returned error, its gRPC code, and broker logs and connection events. Read broker message statistics before and after each step (channel and vhost `message_stats.return_unroutable` and `drop_unroutable`). The unit fixtures use loopback protocol peers, not RabbitMQ.

1. Create the bound `qualification.events` queue and binding. Let the publisher declare the `qualification.missing-binding` fanout exchange with no binding. Capture `rabbitmqctl list_bindings source_name destination_name --formatter=json` before and after every unbound publication; it must show the control binding and no binding for the missing-binding exchange.
2. Publish one unique routed ID. Require success and exactly one persisted effect.
3. Publish one unique unbound ID. Require one failed attempt with a FailedPrecondition error naming reply code 312 and `NO_ROUTE`, no component retry, a `return_unroutable` increment of one, and zero effects for that ID. Record the elapsed time against the 3000 ms outbound budget. A success, generic timeout or retry exhaustion fails the step.
4. For that unbound publication, record the wire order of `basic.return` and `basic.ack` on the publisher's channel, with frame timestamps, for example from a capture on a fixture-owned non-TLS listener or broker trace for the harness connection. Require the return before the ACK carrying the same delivery tag; any other order is a recorded failure, not a reason to reinterpret step 3.
5. Start at least sixteen concurrent publications, alternating the bound and unbound topics, all with the same application message ID. Every unbound call must fail with the step 3 error and every routed call must succeed. Effects must equal the routed count, and `return_unroutable` must equal the unbound count.
6. Pause the broker only during a distinct unbound mandatory publication with the existing one-second client timeout; unpause in cleanup. The result must be non-success and uncertain, never a conclusive unroutable claim. Package A's transport abort closes the shared connection. Before the pause, deliver a separate ID to a consumer without acknowledging it. Afterwards, prove that subscriptions resume, the unacknowledged ID is redelivered (receipts at least two, effects exactly one) and a later routed publication succeeds on a new connection generation.
7. Force a connection replacement between publications (`rabbitmqctl close_connection` for the publisher connection). The next routed publication must succeed on the new generation, and no earlier return may fail it.
8. Restart without `publishMandatory`. An unbound publication must reproduce the historical default: success, with no mandatory flag on the wire. Then configure `publishMandatory: "true"` with `publisherConfirm: "false"`; component initialization must fail with the error naming both fields.

These steps cover the I/O matrix rows of the spec against a real broker. Mismatched returns and stale returns on a live channel cannot be produced on demand by RabbitMQ. They remain covered only by the protocol-peer and fake-broker tests. A forced reconnect after an unresolved attempt also resets the shared connection; step 6 measures that consequence.

## Dapr evidence and later full-matrix admission

The unchanged predicate requires HTTP 400–598, physical binding absence before and after, and `allowedEffects == 1`. Retain the full response, `google.rpc.ErrorInfo`, elapsed time and ID-based readback. This package does not claim how the runtime maps the component's FailedPrecondition error to HTTP. The components-contrib `pubsub/errors.go` helper documents that, without a resiliency retry `matching` rule, the runtime retries every publish error regardless of code. The measured response under the actual resiliency policy decides; neither the predicate nor the request changes.
