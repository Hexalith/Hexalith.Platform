It excludes transport attempts and current private proof bytes so lookup retains the same original. Static result validation rejects incompatible operation/status/receipt shapes; it grants no physical authority. The whole request remains subject to **separate exact private authentication** over `CustodyBindingContract.Encode(exact)` and the distinct method, including operation ID, phase, enrollment, current control proof, key-use recipient/transport and attempt/challenge. An unkeyed digest cannot replace the independently computed retained-key fingerprint/private credential verifier. This seam defaults to denial and has no installed implementation.

The full original-result bound is independent of the actor pending-state cap. A closed original contains at most 1,000 receipts, each with five strings of at most 2,048 UTF-16 units, at most six JSON bytes per unit. `1000*(5*2048*6+256) + 16*2048*6 + 16384 = 61,908,992` is below the local 64 MiB assembly cap and includes conservative wrapper/signature overhead. The large synthetic original from owner-accepted input is 37,272,584 bytes, SHA-256 `01DA84829255A7CE0DFEB1D13F45C98D80216D78DB526DDD23F6388B19A8D15B`, and needs 143 pages. Its tenant is 64 ASCII characters and batch is 256 valid ASCII characters. This is an honest large legal-input measurement, not a tight legal maximum or a physical outcome. The 64 MiB cap remains a conservative structural upper bound. Every page and the whole assembly share the caller's deadline (at most 30 seconds). Actual completion at this bound still needs component throughput/memory measurement. No key-bearing material is paged. The 32 MiB inherited pending-transition limit remains unchanged; a legal 32 MiB transition's base64-encoded binding request also cannot fit the default 4 MiB transport.

Count limits are not byte-capacity proof. The representative full ledger at 1,000 registrations/10,000 retained requests measures 12,789,051 bytes, leaving 20,765,381 bytes against the unchanged 33,554,432-byte pending cap. A separate structural field/count witness measures 3,947,414,309 bytes using equal-width serialized entries and exact JSON-array accounting. That witness exercises allowed field/count sizes; it does **not** claim a reachable admitted revision history or a physical original schedule. No checkpoint/provider headroom is proved. Before production admission the component must reserve concrete bytes, native intents, immutable result retention, holders and completion capacity; inability to reserve denies admission while preserving existing limits and already admitted completion.
