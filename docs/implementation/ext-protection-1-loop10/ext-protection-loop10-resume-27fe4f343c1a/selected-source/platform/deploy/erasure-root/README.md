# Prepared A1 erasure-root custody

These files are prepared only. They have not been applied. They do not qualify the all-copy contract or authorize a Live run.

The dedicated namespace, single OpenBao 2.6.2 instance, persistent volume and native key hierarchy are separate from `hexalith-keys` and ordinary HMAC custody. `DurabilityPolicy.None` means there is no backup/restore recovery path. Volume loss permanently loses every protected payload. No automatic initialization, unseal, root-token retention, auto-unseal installation or key export is supplied.

The namespace, pod, StatefulSet and PVC exclude Velero backups. The distinct `hexalith-erasure-root` selector prevents reusing the ordinary OpenBao workload identity. Before any future application, the actual daily snapshot job, Story 4.0 off-node jobs, storage snapshot policies, node/volume backups, support bundles and recovery/operator paths must independently exclude this namespace and volume. These manifests cannot control an out-of-repository backup job or an administrator's root access. No scheduling exclusion is claimed installed.

`namespace.yaml`, `statefulset.yaml` and `network-policy.yaml` require an independently installed `erasure-root-tls` TLS Secret and an independently qualified `erasure-root-no-backup` storage class whose snapshots/backups are excluded. The prepared claim requires that exact class and cannot fall back to the cluster default; no class is installed by these files. Client ingress is the explicit `hexalith` namespace on TCP 8200. Port 8201 remains on the headless Service for raft and is not admitted to those clients. The namespace carries restricted Pod Security labels matching the non-root, capability-dropped container. `bootstrap.py --apply` renders one policy per installed tenant and genesis scope, limited to that tenant's head path and transit key. The shared `custody-policy.hcl` file is the deny fragment for export, backup, and restore; it is not a production credential and does not grant `tenants/*`. Runtime credentials cannot create/delete keys, export/backup/restore keys, list/read head metadata or invoke a Raft snapshot. Trusted operator/root credentials can bypass those ACLs and therefore remain part of the required copy inventory.

`bootstrap.py` defaults to public-input validation with zero effects. Its independently reviewed JSON enrollment must contain exactly `address`, `storeId`, `enrollmentId`, `transitMount`, `headMount`, `nativeKeys` and `genesisAnchors`. `nativeKeys` maps each canonical tenant to its distinct native key name. `genesisAnchors` maps each tenant to its independently selected owner-scope/genesis-SHA256 pairs. Empty or guessed genesis is refused. Example validation, after a real public enrollment exists:

```sh
python3 deploy/erasure-root/bootstrap.py --enrollment /absolute/independently-reviewed-enrollment.json
```

The separate `--apply` switch is reserved for a later expressly authorized provisioning task. It requires `--ca-certificate /absolute/erasure-root-ca.pem`, the same dedicated CA pinned by the production store, and uses `env:ERC_BOOTSTRAP_TOKEN` by default. Its TLS context trusts only that CA file and validates the peer before writing the bearer. It creates no credential, never initializes/unseals OpenBao, creates each transit key with `deletion_allowed: false`, installs each rendered tenant/scope policy, and reads that policy and each CAS-0 head back before it reports bootstrap. A missing policy readback or a head that does not match the written bytes refuses. Each invocation reads the native mount inventory and existing key/policy/head: exact matching objects are retained, absent objects are created, and a conflicting object stops before it is changed. Heads are created only with CAS=0. A failed or lost acknowledgement is not retried within that invocation; a later explicit invocation reconciles the same enrollment. Failure JSON identifies the stopping step without remote bodies or credentials. Default `--apply` off stays zero native calls. A bootstrap result is always unqualified.

Each tenant policy allows minimum encryption and decryption versions 1 through 64, including bootstrap epoch 1 and subsequent trims. This is a prepared epoch bound; using a later epoch requires a separately reviewed policy update. The listener retains `max_request_size = 67108864` and `max_request_json_memory = 134217728`; their 192MiB sum fits under the 1Gi container limit while accepting a head near the 30MiB cap.

Kubernetes Pod resources have no Docker-style combined memory-and-swap setting. The prepared container retains its 256Mi memory request and 1Gi memory limit. The independent node prerequisite is Linux cgroup v2, a compatible CRI runtime, a container cgroup namespace exposing its own limits at `/sys/fs/cgroup`, and kubelet `memorySwap.swapBehavior: NoSwap`. The prepared [kubelet fragment](kubelet-noswap.fragment.yaml) must be merged into the actual node configuration by its owner; it is not a workload manifest or an apply input. Kubernetes directs the CRI runtime to prevent workload swap under [NoSwap](https://kubernetes.io/docs/concepts/cluster-administration/swap-memory-management/). The [cgroup v2 memory controller](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html#memory-interface-files) defines `memory.max` for memory and `memory.swap.max` for swap separately. Thus `memory.max = 1073741824` and `memory.swap.max = 0` impose a combined 1Gi ceiling. The shipped startup script checks those exact fixed kernel paths before executing OpenBao and refuses missing, unlimited or different limits. It has no configurable path bypass. Equal requests and limits are not used as proof. Node configuration, runtime enforcement and mounted limit files remain independently required and unverified here; these files were not installed. This container check does not establish erasure of host memory or system-daemon swap.

The all-copy acceptance blocker remains. Native transit trim removes old versions from the live native inventory and refuses old ciphertext; this does not establish destruction of historical Raft entries, database pages, memory, swap, core dumps or operator copies. Snapshot exclusion alone is insufficient for the register's complete all-copy requirement. These preparation files do not bypass that blocker.

Rotate creates new versions only. Each retained original manifest selects its successor explicitly, and every wrap/rewrap specifies that head-selected version. Concurrent/delayed rotations may create unused newer versions; trim destroys only versions below the selected successor and leaves all newer versions intact. Component tests cover this recovery schedule and subsequent root issue. This still requires native verification before a production claim.

Immutable transition payloads and completed holder identities use create-only, CAS-zero entries below `erc-heads/data/archives/<tenant-sha256>/<identity>`, inside this same snapshot-excluded ERC. The tenant CAS head retains current revision/digest, exclusive pending admission and committed archive ancestry pointers; an unreferenced prewrite never establishes completion. Runtime policy grants archive `read`/`create` and no archive update, deletion, metadata or restore. Current owner reads authenticate the committed tip; exact historical reads walk its authenticated predecessors. Complete legacy in-head transition chains migrate under one tenant CAS; incomplete chains refuse writes until their exact safe migration is resolved. Active/unknown holders remain restrictive in the tenant head. Cleared process-owned holders are retired by the production host worker; a zeroed root alone does not retire an undisposed consumer scope.

Native transport admits heads up to 30 MiB and reserves the remaining response allowance for KV metadata/framing. Its configured operation deadline includes streamed response-body reads. Bootstrap refuses every redirect before forwarding the native bearer credential. These are prepared source/ACL rules, not an installed permissions or full-copy qualification claim.

Loop-two storage keeps completed manifest originals, prepared survivor payloads and exact guard admissions/outcomes in immutable same-ERC archives. Prepared survivors bind the complete manifest digest, original reservation and both epochs; the authoritative tenant CAS pointer is required before trim. Pending/terminal head capacity is checked before rotation and again before trim. Large current transitions support the existing 32 MiB EventStore bound through authenticated 4 MiB chunks with a 48 MiB serialized-original bound and the existing 12 MiB native archive-entry bound. Completed manifests contain no survivor payload or survivor pointer. No archive prewrite grants completion.

Readiness uses the pinned native `bao read sys/health` command over HTTPS with `/bao/tls/ca.crt` peer validation. That CA file is an additional required member of the independently installed TLS Secret. Native health must report initialized, unsealed active custody with its normal successful status; sealed/uninitialized/standby responses cannot make the prepared pod ready. The independent source receiver installs its own verifier-holder lifetime worker, even when its custody instance differs from EventStore's. Canonical qualification seed originals require the separately installed `RetainQualificationSeedOriginal` private permission; absent permission or exact retained seed provenance refuses before a new role/source admission.

Loop-6 lifetime retention commits fixed root pointers for exact erased identities, completed manifests, lifecycle outcomes, owner anchors and guard/qualification histories under the same tenant CAS. It retains all immutable historical records in the dedicated ERC, without a historical pointer dictionary in the head. Existing exact flat state is read and migrated only with explicit `MigrateLifetimeIndex` authority; later saves require `RetainLifetimeIndex`. Conflicting legacy/index originals refuse before effects. Each independently bound qualification attempt is limited to 1,024 active operations; historical bindings remain indexed. This is an explicit active cohort bound, not a limit on retained historical identities.

Graceful owning-host shutdown closes root/verifier admission and waits for admitted operations and live engine consumers before a final completion drain. The drain uses an independent ten-second deadline even when the host token is canceled. Only genuinely disposed, cleared issued instances can complete. Denied/unavailable completion and still-live/crashed/unknown consumers retain restrictive native membership after the deadline.

Independent source originals use explicit `erc-source-chunks-v3-1m` framing with 1 MiB raw chunks, preserving existing keys/digests and the former null-format 4 MiB reader. Actual Dapr 1.18.7/state.redis verification covers exact 9 MiB and 32 MiB source state, a supported 768 KiB opaque snapshot, fresh readers and dead-ERC typed-Erased replay. The engine's existing 1 MiB protected-content limit is unchanged. New frames fit the default 4 MiB sidecar request/response limit. Reading already persisted 4 MiB raw chunks requires **both** a sidecar response allowance of 8 MiB (`--max-body-size 8Mi`, or the corresponding independently installed Dapr configuration) and the 8 MiB SDK receive setting from `ErasureRootDaprTransport.Configure`. The default legacy response refusal and the exact successful 8 MiB read were separately executed. Apply the helper at the first Dapr client registration or explicitly supplied source client; later default registrations do not override an existing client. No sidecar setting is installed by these preparation files.

Whole-snapshot auxiliary replay metadata now retains only a fixed format, layout tag and independently bound target. Erased opaque snapshots replay the typed `Erased` marker; the explicit canonical envelope replays only `ProtectedContent.Target` and an Erased value. Arbitrary encrypted siblings, names and values are never copied into this metadata. Former opaque V2 originals with absent metadata retain authenticated permanent-loss/manifest-erasure replay. Previously copied whole-object skeletons require independent sanitization and remain unqualified; this change does not erase plaintext copied by a former writer.

The shipped bootstrap `--apply` was exercised only against an owned disposable native OpenBao installation with complete independently supplied multitenant owner genesis. Normal shipped mounts, six exact genesis scopes and real runtime authorities/two lifecycle actors were checked under a restricted runtime token. This is local integration evidence; cluster manifests remain unapplied and production/bootstrap acceptance remains independently gated. Store and enrollment identities must be canonical strings of 1–256 characters matching `[A-Za-z0-9][A-Za-z0-9._-]*` before any native request.
