# Offline custody shared-cut model (I1/F0)

This is source feasibility evidence for the approved Dapr custody continuation. It is not a physical provider, lifecycle adapter, Dapr component, qualification receipt or installed authority. EXT-SECRETS-1 remains unavailable. No network, provider SDK, key material, credentials, native experiment or Live qualification is used.

`CustodySharedCutModel` is internal and has no provider interface or DI registration. Its copy graph carries complete existing `CustodyKeyObjectIdentity` values, selected/survivor membership and four symbolic epoch paths: source, successor, alternate and tainted. The exact supplied original contains operation, batch, protection reservation, request digest, existing manifest digest, complete ordered identities and arbitrary value-free symbolic outcome/signature bytes. It uses the existing manifest-digest primitive and validates supplied order; it never edits signed membership or mints an irreversible receipt. The model keeps the independent head, allocation exclusions, paths and original separate from the application snapshot head.

The B0–B5 schedule reserves the exact protection original, freezes whole-tenant preparation, prepares survivors only, closes prior native sends and all holder incarnations, retires alternate/tainted paths, adopts the successor, removes the common source epoch once, verifies a restore barrier and publishes the original symbolic bytes. Current-authority loss denies effects and terminal lookup. Restore/restart never rewinds the independent graph or original. Lookup and delayed duplicate execution make no effect; an already admitted duplicate key send never releases another key. A lost sidecar leaves its old uncertainty outstanding. Earlier effective/unknown pins block effects; post-dispatch attempts cannot grant a conflicting pin. Stale head comparisons fail. Rotation preserves original identities/AAD, and new survivor admission after arm survives publication and application restore.

`CustodySharedCutModelTests` explores every model action from a two-target/one-survivor initial state, breadth first, through depth 16 with an enforced 150,000-state cap. The bound includes one original operation, four epochs, one routine rotation and one post-arm survivor allocation; authority loss/recovery, restart and old application restore can interleave throughout. Reaching the cap fails the test rather than silently truncating it. The report states the actual visited-state/transition counts and frontier depth. These finite bounds are not an unbounded correctness proof or an implementation of the actor's 10,000-request ledger.

Explicit schedules additionally exercise 1 target with two survivors and 1,000 targets in a separate lane with no survivors, respecting the existing 1,000-registration bound. Every B0–B5 boundary (plus the initial state) has crash, lost-response, old-snapshot and sidecar-loss schedules. Those schedules lose current authority, attempt forbidden effects/replacement, recover the same independent authority, perform read-only lookup/duplicate delivery and finish only the original admitted worker. Negative controls intentionally corrupt the graph/transition to retain concrete traces for partial target cut, survivor loss, early false completion, arm with uncertain buffers and old-provider-state resurrection. Passing tests requires the independent invariant checker to detect each unsafe control.

The complete Local audit includes this test class and persists `custody-shared-cut-model.json` next to its XML evidence. Focused execution can set `HEXALITH_CUSTODY_MODEL_REPORT` to an external evidence file. The report contains only synthetic identities, counts, assumptions and traces; no content, key or credential values.

The following remain assumptions, not proved mechanisms:

- A linearizable independently surviving forward authority retains exact originals and cannot be recreated from application backup. Initial enrollment/current authorization and exact hold-release/owner ordering proofs are correct; authority replacement remains unsupported.
- The complete copy graph accounts for every real copy. Removing the shared source epoch is truly all-target, irreversible physical erasure. Alternate/tainted retirement is permanent deletion, not scheduling, disablement, authentication refusal or missing-key denial.
- Native-send and holder closure actions mean actual original I/O completion and SDK/sidecar/component/UDS/gRPC/TLS buffer completion or accepted termination evidence. A timeout, process restart or credential revocation alone supplies no closure.
- Survivor recovery and the independently verified all-copy restore barrier are correct. Symbolic original bytes do not prove signatures, evidence authenticity, physical destruction, key zeroing or retention.

Actual component/provider feasibility, independently placed runtime authorities and observers, Dapr encoding/limits/retry behavior, transport memory closure, physical restoration tests, numerical retention/capacity and accepted owner qualification remain incomplete. F1 must reject a transport/component that cannot satisfy these conditions; this model grants no native application bypass or permission to execute F2/F3.
