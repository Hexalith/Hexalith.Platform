# Story 4.27: retire KubeSphere

The exact live deletion set is produced by [4.26 qualification](QUALIFICATION.md). This handoff defines the execution contract; the UID-bound command set and procedure approval are not yet recorded.

## Open the retirement gate

- Require accepted 4.26 ownership/dependency mapping, independent private native administration and representative isolated rehearsal.
- Bind the reviewed removal procedure and resource allowlist digest to the current attempt, Administrator approval, window, every affected workload owner's outage acknowledgement and accountable incident/recovery/stop decisions.
- Independently verify current encrypted immutable off-node native workload proofs, external-etcd recovery and node/configuration recovery inputs. Revalidate Story 4.0 freshness/signatures/final-validation bindings and remote readability. Its `done` status never replaces those checks.
- Capture authenticated source health and exact namespace/controller/admission/storage/PVC identity census. Drift, missing proofs, unreviewed propagation/finalizers or unresolved required functionality closes the gate.

## Execute only the qualified scope

1. Archive required KubeSphere configuration/metadata encrypted under restricted custody. Rehome required extensions/controllers and ownership before removing the corresponding reconciler.
2. Apply only the separately approved version-specific, UID-bound uninstall order. Protect application/data namespaces, PVCs/PVs, shared CNI/storage/ingress/identity components, unrelated CRDs and public application/OIDC contracts. No wildcard namespace/CRD deletion or blanket finalizer stripping is permitted.
3. After each dependency phase, compare actual changes and workload state with the approved allowlist and preservation assertions. An unexpected deletion, drift or failed health assertion stops further mutation and retains diagnostics.
4. Verify absence of retired releases/controllers, obsolete API services/admission dependencies and public console route. Any intentionally retained inert archive has a named owner/disposition; unresolved KubeSphere runtime or admission dependencies block completion.
5. Prove native API/private admin, DNS/CNI/storage/admission health, unchanged protected namespace/PVC identities/bindings and authenticated workload outcomes. Verify external public-console denial.

## Close and hand off

Sign the resource-change result, before/after comparisons, health/access outcomes and sanitized summary against the attempt/runbook identities. Missing or failed evidence does not complete 4.27. Preserve old recovery sets; collect a fresh post-retirement etcd point and matching configuration inventory for 4.1 so routine recovery does not resurrect the retired manager.

Do not improvise a kubeadm downgrade, overwrite live PVCs or restore old etcd into a running cluster. A source-preserving recovery plan names its approved target/cutover/fencing decision; an old-point recovery explicitly reconciles retired controllers and authority before reopening.

Retirement completion permits Story 4.1 to finish its remaining gate preparation. It does not authorize a drain, binary replacement, hop or Rancher installation. Preserve the earlier hashed upgrade procedure and create its successor from the actual post-retirement census.
