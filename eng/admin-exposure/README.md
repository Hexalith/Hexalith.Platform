## Retained-digest GC

Leave GC disabled unless the signed retained source is exhaustive. Enumerate roots from current live digests, every rollback-set digest and every signed retained-release record, then traverse indexes, **all** platform manifests, configs/layers, artifact manifests/referrers, signatures, attestations and Helm/chart artifacts. Perform referrer discovery in addition to following forward references. Missing retained source or unknown referrer discovery closes the gate.

`retained-oci-closure.json` contains roots and objects with digest, kind and references; a reference includes discovered reverse referrers so every retained object is reachable from a root. Supported kinds are index, manifest, config, layer, artifact, referrer, signature, attestation and chart. Bind the exhaustive signed source hash and registry generation. Compute `closureSha256` over `canonical({roots: sorted(roots), objects: sorted(objects, key=digest)})` using the helper's canonical JSON encoding. The graph check rejects missing children/referrers, duplicate objects, unbound objects and mismatched hashes; it cannot discover an object omitted from the supplied source. Review the actual traversal/audit evidence independently.

Bind the approved Zot GC/retention configuration and prove every closure object is excluded from deletion. Run an actual dry-run or disposable-repository rehearsal including retained and explicitly disposable content. Acquire the approved registry-wide writer/**replication** lock or qualify an equivalent atomic generation, verify the exact signed generation, then run GC. Stop on any concurrent mutation or generation change. From empty disposable stores, authenticated manifest/index/platform/referrer pulls and config/layer fetches must return every closure digest, with correlated audit evidence, **after GC and before lock release**. For config/layer operations record `blobTransferred: true` instead of manifest/blob pull flags. Verify content SHA-256 against the returned digest. Release the lock only after all checks pass. A failure requires the approved incident/restore decision and preserves the failed evidence; it never permits deletion of retained data.

The result records excluded digests, GC configuration digest matching the generation's `approvedTargetConfigSha256`, actual retained/disposable rehearsal outcomes, and `writeReplicationLock` identity, registry-wide scope, generation before/after, no-concurrent-mutation observation, acquisition/release timestamps, held-through-verification and evidence hash. Bind `gcStartedAt`/`gcFinishedAt` to the fresh pre-mutation checkpoint and approved window. Post-GC object fetches must use an inventoried reader or source-replication identity; writer pushes and destination-replication operations cannot prove retained reads. Every audit operation, including pre-cutover operations, binds its `consumerId` to that inventoried identity. The checker currently requires the registry-wide lock form; an atomic-generation alternative needs an explicitly approved concrete equivalence before extending this local schema.
