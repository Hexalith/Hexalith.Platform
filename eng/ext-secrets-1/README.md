Protocol endpoints and schemas
------------------------------

Only Dapr service invocation is used: `POST http://127.0.0.1:3500/v1.0/invoke/{enrolled-app-id}/method/ext-secrets-1/v1/{operation}`. Operations are enrollment `enroll`, executor `execute`/`lookup`, and independent observer `observe`. A mounted `file:/absolute/path` Dapr API-token credential reference is read transiently for the header; no direct OpenBao/production/SSH fallback or redirect exists. One total monotonic 1–30-second deadline covers credential read/connect/request/headers/body, including continuously trickled input. The caller aborts the connection at that deadline; detached transport work cannot write state or evidence. Responses have a 1 MiB bound, and duplicate JSON properties/nonfinite numbers are rejected. A lost execution result still gets exact original lookup only.

Common request fields are `protocol`, `runId`, `targetCommit`, `isolatedTargetId`, `planSha256`, and deterministic `requestId`. Protocol is `EXT-SECRETS-1.qualification.v1`. Enrollment adds `operation: "enroll"`. Each case adds `caseId`, the independently enrolled `caseTargetId`, `enrolledScope`, and `scenario` containing allowed outcomes, exact required metrics, boundary and four persisted stages. The request ID is SHA-256 of that canonical request before `requestId` is inserted. The client retains `live-plan.json`; `cases.py` is the complete executable client plan and the fixed review matrix independently tests all mandatory cases. Unknown execution results get one bounded exact original lookup; no blind effect retry occurs. Unknown lookup stops that original unless Unknown is the expressly expected isolated failure-injection scenario.

Every response is exactly `{ "payload": { ... }, "signature": "<canonical-base64 64-byte r||s ES256 signature>" }`. The signature covers the canonical ASCII JSON payload, with a P-256 public PEM anchor pinned by the authoritative accepted binding. Every payload adds `identity`, `version`, UTC epoch-second integer `observedAt` and exclusive `validUntil`. Proofs are current within 30 seconds, valid for at most 30 seconds, and checked against the exact independently enrolled identity/version. No `Pass`/`Available` flag or extra unvalidated field is accepted.

Enrollment returns the common binding plus `targetClass: "IsolatedQualification"`, `productionMutationAllowed: false`, `executorIdentity`, `executorVersion`, `observerIdentity`, `observerVersion`, `qualifiedReferencesSha256`, `currentProfileStatus: "Current"`, `currentProfileSha256`, the exact ordered `completeCaseIds`, `caseTargetIds`, and `caseScopes`. The profile hash covers exact runtime `profileReference`, issuer, audience, version, validity and accepted timing. Each scope has `tenantId`, nonempty disjoint `targetIds`, `providerCopyIds`, `logicalId`, `sealId`, `batchId`, `manifestDigest`, `initialAttestationOrdinal`, `initialKeyVersion`, `successorKeyVersion`, `exclusiveExpiry`, `issuer`, `nonceDigest`; all are public references, integers or hashes. Tenant must be enrolled tenant A/B or reserved system; logical ID equals that case's isolated target ID. This is an independent installation guarantee, not an implementation supplied by this client.

Before every new `execute`, the client refreshes the same enrollment request, verifies its fresh signature/exclusive validity and current exact profile, and requires the identical run, authorities, case-target/scope map and original expiries. Only observation validity can advance. The executor still must perform its own current authority check at the actual effect. The refresh grants no capability, delivery, nonce or logical-command renewal. Lookup recovery uses its original request without minting a new effect identity.

After the original is durably published, the client rechecks exclusive enrollment/profile validity immediately before `execute`. Publication can exhaust that window. Such an original remains started in the journal and a later authorized invocation can only use exact lookup; it cannot repeat the effect. An expired installed current profile blocks qualification and lookup pending independently current read authority. This is a current-trust prerequisite, distinct from an expired original delivery envelope or a non-expiring deletion capability. Do not bypass trust, change accepted config pins automatically, renew an original identity/expiry, or delete the original journal to recover.

Executor returns common/case bindings, `outcome` and `resultSha256`. Its exact lookup returns that same immutable original result after loss, restart or restore. `resultSha256` identifies the original content-free outcome/receipt, rather than a fresh attempt or a new release/sign/consume authorization.

Recovery preserves operation-native outcomes: lifecycle Destroyed, delivery Delivered, signing Signed, replay Recorded, consumption Consumed, compromise block ConsumptionBlocked, activation Unconsumed, guard issue Issued, dispatch DeletionBatchDispatchAuthorized, and completion CompletionSealed. Signed alone has no issue revision or active consumption credential and grants no destruction authority.
