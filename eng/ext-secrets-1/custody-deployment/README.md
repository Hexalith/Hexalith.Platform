# Custody deployment review bundle

These unapplied templates package `bindings.hexalithcustody/v1`. The present executable contains an uninstalled AWS reference profile inside infrastructure. It is not an adopted mandatory backend or a qualified provider. Applications use only the configured `interaction-custody` and `custody-authorizer` Dapr roles.

Run offline inspection from the repository root:

```bash
python3 eng/ext-secrets-1/custody-deployment/preflight.py eng/ext-secrets-1/custody-deployment/inputs.uninstalled.json
```

Exit 1 identifies every missing input and its owner/action. Input presence alone is `InputsPresentUnverified`, never installation, qualification, availability or permission. The inspector does not render runnable manifests, apply resources, invoke native services or run a worker. Preserve each output under a new name (`--output` uses exclusive creation).

The component-only Dockerfile consumes an explicitly reviewed publish output, checked by `prepare-image.py` against a retained SHA-256 inventory and its independently supplied digest. The script creates a new external container context; it never builds, pushes, installs or runs an image. Only the digest-pinned ASP.NET runtime image is needed in that recipe. Source publishing is validated separately with the exact owner source graph:

```bash
dotnet publish infrastructure/Hexalith.Platform.Custody.Dapr/Hexalith.Platform.Custody.Dapr.csproj -c Release -p:UseHexalithProjectReferences=true -p:HexalithEventStoreRoot=/absolute/reviewed/eventstore --artifacts-path /new/external/artifacts -o /new/external/publish -m:1
```

Record every source revision/dirty-source hash and published file hash. Supply the closed JSON packet `{ "runtimeImage": "<reviewed-registry/image>@sha256:<actual-digest>", "files": { "<every-relative-publish-file>": "<sha256>" } }`, pin that inventory's SHA-256, and supply its matching actual digest-pinned runtime image:

```bash
python3 eng/ext-secrets-1/custody-deployment/prepare-image.py --publish /new/external/publish --inventory /retained/publish-inventory.json --inventory-sha256 <exact-inventory-digest> --runtime-image '<reviewed-registry/image>@sha256:<actual-digest>' --output /new/external/context
```

The existing real 41-file publish inventory has no reviewed runtime-image pin, so preparation remains **Blocked** until the Platform release owner supplies one. The container recipe is reviewable without claiming an installed artifact. No fabricated image, profile or credential is supplied. Protection adapter tests require the EventStore owner's published owner-state port; the installed NuGet graph predates that source seam. Source qualification and the accepted dependency target remain separate owner work; the image recipe does not silently switch package versions.

`component.yaml.in` registers the exact profile hash and scopes the binding, disables automatic output retries, disables telemetry and defines deny-default invocation policy. `workload.yaml.in` places daprd and the component on a memory-backed UDS volume accessible only inside their pod/group, sets non-root/read-only/capability restrictions and embeds no native credentials. Require cluster mTLS, workload admission, network isolation, memory-capture/swap/hibernation disablement, protected socket directory ownership/mode, disabled SDK/HTTP retries/redirects, complete sidecar/SDK/gRPC/native buffer admission and independent I/O/zeroing/termination evidence. Kubernetes settings alone prove none of these conditions. Bind all named references and exact installed profiles before any separately authorized installation.

The independent authorizer must implement `custody-lifecycle/prepare` and `/authorize`: authenticate the mounted scoped credential and complete intent; read independent fresh current authority/control/observer originals; return an exact envelope for the caller's fresh attempt/challenge; sign the exact complete request SHA-256. It receives no key bytes. It must never authorize an arbitrary caller hash merely because a role or digest is present. Private/control/observer issuers and owner genesis require actual owning-service source and installation; their interfaces here do not supply those implementations. Approval keys remain outside this custody boundary.

`worker.yaml.in` is suspended, has no retries and consumes one retained signed packet with permanent identity. Recovery locates original results and never repeats a send-unknown native intent. The worker must retain output on separately protected immutable storage. No scheduler, policy, synthetic enrollment or running worker is installed by this bundle.

Authority, application encrypted copies and originals have distinct recovery classes and actual placement owners; independent authority cannot share the application's restore cut. EventStore still needs owning-source integration and accepted profiles. Complete actual copy/holder inventory, survivor recovery and irreversible physical G1–G7 proof remain installation/qualification gaps. The OpenBao `ObservedRevival` negative result remains unchanged and G1 remains unqualified.

The output binding is local to a daprd instance. The owning custody application, daprd and pluggable component must share this pod (or an equivalently qualified private socket boundary); applications cannot address a remote output binding by its logical name. The workload explicitly requires a separately reviewed `CUSTODY_APPLICATION_IMAGE` and its source composition. A remote EventStore/Platform caller reaches that owning custody application's authenticated Dapr service API; the app then invokes its own local `interaction-custody` binding. The authenticated authorizer is a separate service reached by scoped credential-bound Dapr invocation. No receiving API host/production DI is activated by these library adapters or templates. Missing host integration is source work, not a ConfigMap value. The daprd Kubernetes workload identity/mTLS, trust domain, invocation ACL, API token/access isolation and exact sidecar identity are installation prerequisites. A generic sidecar alone supplies neither private-operation authorization nor holder closure.

The component socket must be `/var/run/custody/private/hexalithcustody.sock`: the socket stem registers `bindings.hexalithcustody`. The native sidecar init container waits for that protected UDS before daprd discovery; require the cluster's corresponding native-sidecar support. See the [Dapr pluggable registration contract](https://v1-18.docs.dapr.io/operations/components/pluggable-components-registration/). Its current registration guidance confirms the same-pod/shared-UDS boundary; exact pinned runtime behavior still requires installed transport qualification.

## Review repair requirements

Image preparation now requires a closed inventory `{ "runtimeImage": "<reviewed-registry/image>@sha256:<actual-digest>", "files": { "<every-relative-publish-file>": "<sha256>" } }`, its exact inventory SHA-256 and the matching `--runtime-image` argument. The preparer emits that literal immutable `FROM` into a recipe with no runtime-image `ARG`; mutable references, interpolation, duplicate JSON properties or a substituted image are rejected. The previous 41-file publish inventory contains no reviewed runtime-image pin. Its post-review context is therefore **Blocked** until the Platform release owner supplies one. Earlier context output is retained as pre-review evidence; synthetic registry pins occur only in regression fixtures and grant no installed/accepted artifact status.

The manually configured daprd now needs explicit Sentry/control-plane addresses, namespace/trust domain, a scoped projected service-account token with its accepted Sentry audience/lifetime, public trust-anchor secret/key references, and matching Dapr/API and app-channel token secret/key references. Automount remains disabled; only daprd mounts the explicit identity token. The receiving host's actual port/protocol are explicit, and its owning source must enforce `APP_API_TOKEN`. The `appId-dapr` Service selects the custody workload and exposes only the pinned internal mTLS gRPC port 50002; HTTP and local API ports stay on loopback and are not exposed by that Service. Cluster identity/RBAC/network policy and actual trust acceptance remain installation prerequisites. The wiring follows the pinned [Dapr 1.18.1 flags](https://github.com/dapr/dapr/blob/v1.18.1/cmd/daprd/options/options.go), [security/token variables](https://github.com/dapr/dapr/blob/v1.18.1/pkg/security/consts/consts.go) and [Kubernetes resolver naming](https://github.com/dapr/components-contrib/blob/v1.18.1/nameresolution/kubernetes/kubernetes.go).

For the uninstalled reference backend, the component and worker each require a separately scoped mounted credential Secret/key and exact shared-credential profile. The selected secret item is mounted as `/credentials/credentials`; `CUSTODY_REFERENCE_CREDENTIAL_FILE` and `CUSTODY_REFERENCE_CREDENTIAL_PROFILE` are consumed explicitly by infrastructure. Only one selected profile with access/secret keys and an optional session token is accepted; role/process/metadata profile sources and the SDK default credential chain are excluded. `AWS_EC2_METADATA_DISABLED=true` is also required. No credential value belongs in an input ledger or evidence.

The worker sets its configured group as both `runAsGroup` and `fsGroup`, with `OnRootMismatch` ownership handling. The storage owner must verify the actual CSI/PVC supports that ownership and that the exact retained output path beneath `/retained` is writable before authorization. `prepare-original` must exclusively create its original output there; a root-owned unwritable path, ephemeral output or overwritten original is not a supported preparation result.
